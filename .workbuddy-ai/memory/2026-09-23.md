# 2026-09-23

## ExtremisBrowser — Chrome UI/UX redesign (major)

Ported the whole app from the old purple/"extremis" look to a Google Chrome (Android)
design system, and fixed several real bugs.

### What changed
- **Design tokens** — `values/colors.xml` rewritten to Chrome's palette (white surfaces,
  `#F1F3F4` omnibox, `#202124` text, `#5F6368` muted, `#1A73E8` blue, `#DADCE0` outline,
  `#202124/#35363A/#E8EAED/#9AA0A6` incognito). Legacy names (`extremis_blue`, `url_bar_*`,
  `chrome_*`) kept as aliases so untouched files still compile.
- **New resource files** — `values/dimens.xml`, plus text/toolbar/sheet-row styles in
  `values/themes.xml`. Theme restructured as `Theme.ExtremisBrowser.Base` so
  `values-v31` can add the splash items without clobbering the base.
- **Toolbar** — Chrome omnibox row: back arrow (only when `canGoBack`), omnibox pill with a
  dynamic leading icon (search / lock / info / incognito) and focus-to-white behaviour,
  Chrome's outlined square tab counter, 3-dot menu.
- **Bottom-sheet menu** — the old `PopupWindow` menu is now a `BottomSheetDialog`
  (`dialog_browser_menu.xml`) with Chrome's quick-action icon row. **All rows funnel through
  `LinearLayout.addMenuRow(...)` which calls `dialog.dismiss()` before the action**, which is
  the fix for "clicking an option should hide the modal".
- **New Tab Page** — Google-coloured wordmark, Chrome search pill, "Most visited" tile row
  (first tile is `updates.today`), and a "Recently visited" feed rendered as Discover cards
  from real history with tip fallbacks. Removed the placeholder junk text.
- **Tab switcher** — Chrome tab cards with favicon + title + close, blue selected outline,
  dark incognito cards.
- **Library screens** — Bookmarks / History / Downloads / Settings rewritten as Chrome-style
  flat lists with favicons, per-row overflow menus, search fields and proper empty states.
- **New** `utils/FaviconLoader.kt` — in-memory LRU favicon loader (no image library in the
  project). Never fires from incognito tabs.
- **Removed dead code** — `HomeBookmarksAdapter`, `item_home_bookmark.xml`, `menu/main_menu.xml`.

### Bugs fixed
- Overflow menu never dismissed on option tap.
- `binding.webView.visibility == View.VISIBLE` was always true (the WebView's own flag stays
  VISIBLE inside a GONE parent), so system back never exited from the New Tab Page. Added
  `isShowingWeb()` which checks `swipeRefresh` instead.
- Hint text colour on both search fields was the primary text colour, not the muted colour.
- `ic_arrow_forward_24` was actually a left arrow; several icons had malformed paths.
- Voice/camera search were "not available" toasts; voice now uses `RecognizerIntent`,
  camera opens Google Lens.

### Build environment notes (important, cost real time)
- `local.properties` pointed at `C:\Users\Fahim\...` (a different machine). Backed up to
  `local.properties.bak` and repointed at the real SDK.
- `debug.keystore` is gitignored and was missing — regenerated with `keytool`
  (`androiddebugkey` / `android`).
- The Gradle daemon crashed with `EXCEPTION_ACCESS_VIOLATION` in `jvm.dll` during
  `compileDebugJavaWithJavac`. Fixed by adding `-XX:TieredStopAtLevel=1`, `org.gradle.workers.max=2`,
  `org.gradle.parallel=false` and `kotlin.compiler.execution.strategy=in-process` to
  `gradle.properties`.
- AAPT2 rejects `&apos;` / raw apostrophes in `strings.xml` with "Invalid unicode escape
  sequence" — just avoid apostrophes in string resources.
- `rm -rf ~/.gradle/caches/transforms-4` is blocked by the sandbox's safe-delete guard;
  retrying the build works instead.

## KoiBrowser feature port (second request, same day)

User asked to "copy all the features and the UI, logic and functionality" from the sibling
`KoiBrowser/` project into `app`. KoiBrowser is a 152-file / ~19,700-line **Java** app
(compileSdk 34, minSdk 21, Dagger 2 codegen, EventBus/otto, RxJava shims, 4 local `fetch2` AARs,
three jcenter-only deps). Our app is Kotlin on minSdk 24 with no codegen.

**Decision (user chose it):** keep the Chrome UI we built and re-implement KoiBrowser's
*features* natively in Kotlin. KoiBrowser's own UI was NOT adopted — it is a different design
language (tab drawer, `MaterialSearchView`, bottom settings sheet).

### What was added
- `tabs/TabSession.kt`, `tabs/TabManager.kt` — real multi-tab engine: one WebView per tab,
  reparented into `binding.webHost`. Mirrors KoiBrowser's `TabsManager` removal semantics
  (close current -> next tab if one exists to the right, else previous). Tabs serialise to
  JSON in prefs (`BrowserPreferences.savedTabs`); incognito tabs are never persisted.
- `utils/BrowserPreferences.kt` — every KoiBrowser setting behind a typed accessor. Uses plain
  `SharedPreferences` (NOT `androidx.preference`) so no new dependency.
- `utils/SearchEngine.kt` — 8 engines with KoiBrowser's exact query URLs.
- `utils/SuggestionsProvider.kt` — Google suggest endpoint, ISO-8859-1 encoded query, gzip,
  1-day disk cache keyed by query-URL hash, offline fallback.
- `utils/AdBlocker.kt` + `assets/hosts.txt` (44,881 domains, 1.2 MB) — blocks via
  `shouldInterceptRequest`.
- `adapters/SuggestionAdapter.kt`, `adapters/FileBrowserAdapter.kt`
- `models/FileEntry.kt`, `utils/FileUtils.kt`, `FileBrowserActivity.kt` + its two layouts
- `MainActivity`: per-tab WebView factory, find-in-page, screenshot (MediaStore on API 29+),
  long-press link/image menus, file chooser, fullscreen video, translate, add-to-home-screen,
  panic wipe, clipboard monitor, pop-up blocking, launch-counter rate prompt, `onTrimMemory`
  freeMemory.
- `SettingsActivity`: full settings set (search/content/privacy/library/advanced) with a new
  `addSwitch()` row builder; `item_settings_row.xml` gained a `MaterialSwitch`.
- `AndroidManifest`: `POST_NOTIFICATIONS`, `<queries>`, `FileBrowserActivity`.

### Deliberately NOT carried over (documented in README)
fetch2 AARs / DownloadsService / CustomDownloader -> DownloadManager. Dagger, EventBus,
schedulerUtils, Sugar ORM, TextDrawable, Five Stars, Shimmer, leanback, material-dialogs 0.9.6,
jsoup, Glide, Retrofit -> replaced or unnecessary. Lato fonts and the theme chooser dropped to
preserve the Chrome look.

### Gotchas hit
- **Two parallel `Edit` calls to the same file clobber each other.** The second edit rewrites
  from the pre-first-edit content, silently dropping the first change. This cost a build cycle
  (`downloadDirectory`, `lastClipboardValue` both vanished). Edit one file at a time.
- `::webView.isInitialized` on *another* instance of a class fails to compile ("backing field is
  not accessible"). Expose a `val hasWebView get() = ::webView.isInitialized` on the class.
- Calling `webChromeClient.onHideCustomView()` from inside our own `onHideCustomView()` override
  is infinite recursion — `hideCustomViewFor` must not re-enter the callback.
- `Environment.getExternalStoragePublicDirectory` direct writes are blocked from API 29; route
  screenshots through MediaStore with `IS_PENDING`.
- `string/close` did not exist; the only resource error in the whole port.
